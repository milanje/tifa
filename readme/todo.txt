Here are some short term objectives:

  - Check tifa_cofactor on real cofactors from a number field sieve (dumps
    from CADO-NFS, for example). So far it has only been measured on
    synthetic cofactors: integers without small factors, of the sizes a
    sieve leaves.

  - Measure and tune on x86-64. All the measurements so far come from one
    Apple M5 Pro, whose 64 KiB L1 data cache gives 64 KiB sieve chunks
    (32 KiB on most x86-64 cores), and the default parameters of SIQS and
    ECM were chosen there.

  - SIQS: outside the sieve, the largest costs left at 70 bits are, in
    shares of a run:
      - the first use of the GMP integers of each run's arrays, about 880
        allocations (12%). Keeping the arrays between runs would need state
        per thread; storing an index of the polynomial's 'a' instead of a
        copy for each candidate would remove a quarter of them;
      - the trial division of the relations (12%);
      - the Gaussian elimination (12%). Gauss-Jordan on the transposed
        matrix was slower, and removing singleton columns would only remove
        2 to 7% of the matrix;
      - each new 'a' (5 to 9% from 70 to 100 bits). One more prime in 'a'
        halves their number, but is slower from 66 to 90 bits with the
        current defaults: it would need retuning them.
